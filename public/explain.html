Multi-Environment CI/CD Pipeline & Static Web Application Structure

Branching & Promotion Flow

The repository enforces GitFlow with a promotion flow: Feature Branch → Develop → Staging → Main.

Feature feature/<username>/<page> - Individual member branches. Pull Request triggers ci-dev.yml.
↓
Develop develop branch - Integration branch. Push/Merge triggers cd-dev.yml (deploys to pakvista-dev).
↓
Staging staging branch - Release candidate checks. PR triggers ci-staging.yml, Merge triggers cd-staging.yml.
↓
Main main branch - Production release. PR triggers ci-prod.yml, Merge triggers cd-prod.yml.

CI/CD Workflows Reference

Workflow File Type Target Branch Docker Tag / Deploy Hook Action
ci-dev.yml CI (PR) develop Lint, Build, Push tags: :dev-latest, :dev-<sha>
cd-dev.yml CD (Merge) develop Triggers Render Dev deployment hook URL
ci-staging.yml CI (PR) staging Lint, Build, Push tags: :staging-latest, :staging-<sha>
cd-staging.yml CD (Merge) staging Triggers Render Staging deployment hook URL
ci-prod.yml CI (PR) main Lint, Build, Push tags: :prod-latest, :prod-<sha>
cd-prod.yml CD (Merge) main Triggers Render Production deployment hook URL
